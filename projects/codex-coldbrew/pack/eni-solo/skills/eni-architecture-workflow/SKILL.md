# 架构分析工作流

## 适用场景

- 完整架构盘点与文档化
- 组件边界与数据流梳理
- 架构级威胁评审
- 为渗透测试与代码审计提供地图

## 工作流阶段

### 1. 组件盘点

把系统拆到能画图的粒度：

- 组件清单：服务、库、中间件、外部依赖
- 接口清单：API、消息、共享存储、回调
- 部署视图：环境、拓扑、扩展点

每个组件记录：职责、语言、关键依赖、负责人。

### 2. 数据流与控制流

- 主链路：请求从入口到落库的完整路径
- 异步链路：队列、事件、定时任务
- 状态：会话、缓存、持久化的分布
- 依赖方向：谁调用谁，哪里形成环

### 3. 信任边界与失败模式

- 信任边界：认证点、授权点、租户隔离、内外网分界
- 失败模式：单点、重试风暴、超时级联、数据不一致
- 安全假设清单：每一条都要能找到实现证据

### 4. 威胁评审

沿数据流逐段问：

- 这段输入可信吗？经过哪些校验？
- 这个身份在此处拥有什么权限？从哪来？
- 这个组件失败时影响面多大？
- 这条链路有哪些可以被外部影响的环节？

输出威胁清单，每条配：位置、前提、影响、现有缓解、待验证项。

### 5. 证据校验

架构声明必须落到源码或运行时证据：

- 声称有校验 → 找对应代码
- 声称有隔离 → 找配置或网络策略
- 声称有监控 → 找遥测埋点

对不上的一律标"未证实"，不写进结论。

### 6. 图表与报告

- 图表走 `eni-diagram`：分层架构图、数据流图、时序图
- 报告结构：资产概览、架构描述、威胁清单、未证实假设、建议优先级

## 证据要求

- 命令、版本、哈希、证据路径、假设与验证结果全程留痕
- 长跑前持久化检查点

## 衔接

- 收尾交付走 `eni-universal-workflow` 的 deliver 阶段
- 图表生成调用 `eni-diagram`
- 威胁清单可直接作为 `eni-pentest-workflow` 的假设积压输入
