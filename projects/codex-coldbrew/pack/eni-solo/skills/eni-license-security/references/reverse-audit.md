# 逆向审计

从启动路径与功能门控开始，一路追踪客户端的验证路径，直到最终的权益判定。

## 定位目标

- 激活端点、请求/响应模型、头部、签名、nonce、时间戳与缓存；
- 密钥解析、规范化、哈希、签名验证、设备指纹、时钟检查、功能开关与错误/回退分支；
- 内嵌密钥/密钥材料、证书固定、更新通道、配置开关、调试端点与遥测；
- 多处重复校验中，其中一条比另一条更强的情况。

## 方法

静态分析配合加密、比较、时间、存储、网络与功能门控附近的断点/hook。把可补丁的分支记录为"客户端信任"的证据，随后把权威判定或关键效果迁移到服务端可控边界。

## API 测试面

针对 API 测试：激活次数、重放、竞态、租户/账户归属、产品/受众混淆、降级、并发、速率限制与错误枚举。
