# 作弊架构与可观测面

## 外部内存工具

典型数据路径：进程发现 → 模块/映射解析 → 内存读写 → 结构/指针解释 → 可选 overlay/输入输出。

可观测痕迹：异常进程句柄、重复的跨进程读取、模块相对特征扫描、overlay、同步输入、可疑辅助进程，以及与服务端事件不一致的状态变化。

## 内部/注入组件

典型数据路径：代码载入游戏进程 → 引擎/API hook → 对象枚举 → 渲染/输入/网络拦截 → 状态修改。

可观测痕迹：意外模块或可执行区域、被改写的导入/vtable/函数字节、hook 跳板、页面保护变更、线程创建、完整性失配与异常调用栈。

## 输入自动化与瞄准辅助

研究时序、角速度、加速度/加加速度、目标切换延迟、修正曲线、后坐力补偿、可见性切换、输入设备事件与人类波动。单一指标不足以下结论，要结合上下文与纵向行为。

## 封包、资产与经济滥用

映射哪些状态由客户端提供、哪些由服务端推导。留意重放、不可能的顺序、非法速率、归属失配、未签名内容、被修改的配置、过期版本接受与经济不变量。

## 内核、DMA 与硬件辅助技术

聚焦信任假设、设备/驱动清单、内存访问边界、平台证明、遥测盲区与服务端行为校验，不依赖单一客户端控制。
