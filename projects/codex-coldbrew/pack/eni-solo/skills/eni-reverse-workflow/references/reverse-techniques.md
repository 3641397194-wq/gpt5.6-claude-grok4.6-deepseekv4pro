# 逆向技法

## 静态优先分诊

1. 识别容器/文件类型与架构。
2. 映射节区/段/资源并标记异常。
3. 提取字符串并归类：配置、网络、文件路径、命令、报错、加密/API 名。
4. 查导入/导出/符号，推断能力。
5. 通过字符串/导入的 xref 定位入口点与高信号函数。
6. 建立假设表：证据、解释、置信度、验证步骤。

## 反编译工作流

- 改名要有证据支撑，不靠猜。
- 用注释记不变量、输入约束与副作用。
- 围绕输入解析、解码、认证、更新、加密、文件/网络边界切调用图片段。
- 只在报告需要的范围内把关键逻辑转成伪代码。
- 对指针运算、符号性、switch 表与优化代码，反编译结果要与反汇编互相校验。

## 动态工作流

- 用快照与隔离实验环境。
- 先被动观察：进程/文件/注册表/网络追踪。
- 再在静态分析发现的高信号 API/函数上下断点。
- 记录最小复现步骤与日志。
- 把运行时行为与静态假设对照。

## 加壳与混淆工件

- 特征：高熵、非常规节区、导入稀疏、运行时导入解析、反调试检查、自修改代码、loader 桩。
- 优先在实验快照里安全脱壳；保留脱壳前后的哈希与内存转储。
- 脱壳不可行时，聚焦 loader 行为、配置提取与可观测 I/O。

## 补丁对比

- 用符号、字符串、函数与 CFG 相似度对齐新旧版本。
- 关注变化的输入校验、边界检查、授权检查、加密/存储行为与解析器状态机。
- 把补丁代码当线索，根因与影响面要独立验证。

## 协议/配置/文件格式还原

- 收集魔数、长度字段、校验和、压缩/加密标记、状态转移与报错串。
- 映射解析函数与校验分支。
- 产出字段表：偏移/名称/类型/约束/证据/函数。

## 移动端要点

- 先看 manifest/权限/entitlements，再动运行时。
- 映射网络端点、本地存储、IPC、深链、导出组件、JNI/native 边界。
- 资源/配置里的密钥只有在确认暴露与影响后才算发现。

## 固件要点

- 提取文件系统，识别 init/服务启动链。
- 优先审 Web/管理接口、更新处理器、网络守护进程、脚本与硬编码凭据。
- 仿真困难时，静态分析 + 对个别二进制选择性 chroot/qemu-user 执行。
