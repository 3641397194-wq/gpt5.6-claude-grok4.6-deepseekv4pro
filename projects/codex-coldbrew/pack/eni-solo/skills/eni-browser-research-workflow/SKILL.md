# 浏览器研究工作流

## 适用场景

- 需要可靠复现的网页数据采集与调研
- 登录态、分页、下载、动态渲染的自动化
- 采集结果的 schema 校验与回放验证

## 工作流阶段

### 1. 人工观察先行

写自动化之前先手动走一遍目标页面，搞清楚：

- 导航结构：入口、跳转、需要点击几次到达数据
- 认证状态：登录方式、会话存续、验证码出现条件
- 数据形态：表格？列表？延迟渲染？分页规则？
- 失败形态：限流提示、反爬页、超时表现

观察笔记直接成为自动化设计的输入。

### 2. 交互建模

把人工路径翻译成可执行模型：

- 元素定位策略：优先稳定属性（name、data-*、文本），避开脆弱的位置选择器
- 等待策略：显式等待元素/网络空闲，少用固定 sleep
- 分页与滚动：翻页规则、加载更多、无限滚动
- 下载：文件名规则、MIME 类型、保存路径
- 错误分支：每类失败页面的识别特征与重试策略

### 3. 自动化实现

- 确定性优先：同样的输入必须产出同样的操作序列
- 重试带退避：网络抖动用指数退避，业务限流用更保守策略
- 截图与 trace：关键步骤留痕，失败时自动存档现场
- 会话复用：登录态只建立一次，后续复用 cookie 上下文

### 4. 采集与校验

- 输出按 schema 归一：字段、类型、必填约束
- 抽检：每批样本人工/半自动核对 5-10 条
- 计数对账：翻页总数 vs 实际入库数
- 唯一键：定义记录身份键，重复导入自动去重

### 5. 回放验证

- 用存档的 trace 或截图回放关键步骤
- 对比两次运行的输出差异，判断是页面变化还是脚本 bug
- 变化超出阈值 → 触发人工复核

## 证据要求

- 命令、版本、哈希、证据路径、假设与验证结果全程留痕
- 长跑前持久化检查点
- 每次运行的配置快照（浏览器版本、UA、代理设置）

## 衔接

- 通用采集需求走 `eni-scraper-workflow`
- 页面交互细节（元素引用、点击、填表）用 `eni-browser-automation`
- 收尾交付走 `eni-universal-workflow` 的 deliver 阶段
